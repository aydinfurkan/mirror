# OpenAPI

Write one OpenAPI 3.1 file in YAML for each `backend` project in `.mirror/xsrc/config.json`.
Each path in this file is relative to `.mirror/xsrc/`.

- Path: `.mirror/exports/<project>.openapi.yaml`.
- The first line: `# Generated by mirror:export from .mirror/xsrc/<project>/. Change the mirror, then export again.`
- Skip a project with no `http` flow.

## Top level

- `openapi`: `3.1.0`.
- `info.title`: the project id.
- `info.version`: today, as a quoted string: `"2026-10-23"`. YAML reads a date without quotes as a date.
- `info.description`: the first paragraph of `<project>/definition.md`.
- `tags`: one entry for each `group` of the flows, in order of first use.
- `paths`: see "Operation".
- `components.schemas`: see "Schemas".

## Operation

Make one operation for each flow with `trigger: http`. Skip each other flow. Skip a flow whose
`entry` is not `<METHOD> <path>`, for example a GraphQL or an RPC flow.

- The path: the path of `entry`. Write each `:name` as `{name}`.
- The method: the method of `entry`, in lower case.
- `operationId`: the flow id, in camelCase. Example: `create-order` gives `createOrder`.
- `summary`: the sentence of `definition.md`.
- `tags`: the `group` of the flow. Skip it when the flow has no group.
- `description`: the text of `## Context` in `business-rules.md`. Then the line
  `Constraints:` and the bullets of `## Constraints`. Skip a part that is empty.

## Input

Read the table under `## Input` of `boundary.md`.

- A path field: one entry in `parameters`, with `in: path` and `required: true`. Add a path
  parameter for each `{name}` of the path, also when the table does not list it.
- A query field: one entry in `parameters`, with `in: query`.
- A header field, or a header that the trigger line names: one entry in `parameters`, with
  `in: header` and `required: true`.
- The body fields: one `requestBody` with `content.application/json.schema`. Put each field in
  the schema at its path. `items[].quantity` is the property `quantity` of the items of the
  array `items`.
- `required`: the fields with `yes` in the Required column.
- The type: the Type column. Use `string`, `integer`, `number`, `boolean`, `array` or `object`.
- The Validation column. Write each limit that maps to a schema keyword:

  | Validation          | Schema                               |
  | ------------------- | ------------------------------------ |
  | `valid email`       | `format: email`                      |
  | `1–10` on a number  | `minimum: 1`, `maximum: 10`          |
  | `1–50 items`        | `minItems: 1`, `maxItems: 50`        |
  | `1–200 chars`       | `minLength: 1`, `maxLength: 200`     |
  | `not empty`         | `minLength: 1`                       |
  | `one of a, b`       | `enum: [a, b]`                       |

  Put each other limit in the `description` of the field. Do not drop it.
- The example under `Example:`: the `example` of the request body. Use the JSON of the fence.

## Output

Read the table under `## Output` of `boundary.md`. Make one entry in `responses` for each
row with an HTTP status. Skip each other row, for example a published event. Tell the user
about it in the report.

- `description`: the When column.
- The schema of the Body column:
  - An error shape such as `{ error: { code: "not-found", message } }`: a `$ref` to
    `#/components/schemas/Error`.
  - A name such as `Order`, or `Product` with a note: a `$ref` to
    `#/components/schemas/<Name>`. Put the note in `description`.
  - A list such as `Product[]`: an `array` with `items` as a `$ref` to the name.
  - An other object shape such as `{ orderId, sessionId }`: an object with these properties.
    Take each type from the example of the same status. Use `{}` for a property with no
    example. A value in the shape, such as `status: "cancelled"`, gives `const`.
  - No body: skip `content`.
- The example under `Example (<status>):`: the `example` of that response. Skip it when there
  is no example.

## Schemas

- Add each name of a Body column to `components.schemas`. Make its schema from the examples
  of the name. Make a type for each value of an example. Use all the properties of all the
  examples. Put a property in `required` only when each example has it.
- `Error`: an object with the property `error`. `error` has `code` and `message`, both
  required, and each other property of the error shapes, such as `field`. Add `Error` only
  when a row uses it.
- Use the same schema for the same name in each operation.

## Check

1. Make sure that the file is valid YAML.
2. Make sure that each `{name}` of each path has one path parameter.
3. Make sure that each `$ref` has an entry in `components.schemas`.

Example: see `examples/openapi.yaml`.
