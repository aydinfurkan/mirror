# Mermaid

Write one Markdown file with Mermaid diagrams: the links of all projects, then one diagram for
each flow and page. Each path in this file is relative to `.mirror/xsrc/`.

- Path: `.mirror/exports/mermaid.md`.
- The first line: `<!-- Generated by mirror:export from .mirror/xsrc/. Change the mirror, then export again. -->`
- Then `# <repository folder name>`.
- Put each diagram in a fence with the language `mermaid`, under its own `##` header.

## Labels

- Put each label in double quotes. Write `"` as `#quot;`, `<` as `#lt;` and `>` as `#gt;`.
- Use `<br/>` for a line break in a label.
- Remove the backticks of the source text.
- Give each node a short id: `n0`, `n1`, … Do not use a flow id as a node id. A flow id can
  have `-` and `/`.

## Links

Header: `## Links`. One `flowchart LR` with the links of each flow and page. The button "Copy
Mermaid" in the graph view of the viewer copies the same links.

1. Make a node for each flow and page: the `entry`, `<br/>`, then the flow id.
2. Make a node for each link target that is not a flow:
   - An external system: its `name` in `config.json`. Use `[( )]` for a `database`. Use `([ ])`
     for each other kind.
   - A project: the project id.
3. Put the nodes of each project in one `subgraph <id> ["<project>"]` … `end`, in the order of
   `config.json`. Put the external systems after the subgraphs.
4. Make one edge for each link. Read the links with "Links" in `flow/boundary.md` of the
   `mirror:formats` skill: the `## Dependencies` of `boundary.md`, and the `Call:` bullets of
   `actions.md`.
   - `calls`: `a -->|calls| b`.
   - `publishes`, `writes`: `a -.->|publishes| b`.
   - `consumes`, `reads`: the data goes to the flow. Write the target first:
     `b -.->|consumes| a`.
   - Write each edge once. Do not write the note of the link.

## Flow

Header: `## <project>/<flow>`. One `flowchart TD`:

1. A start node `s0(["<entry>"])`, then one node for each `## N. <step>` of `steps.md`, in
   order: `s1["1. <step>"]`. Add each bullet under the step to the label, after `<br/>• `.
2. Join the nodes in order: `s0 --> s1 --> s2`.
3. For each link in `## Dependencies` of `boundary.md`, add a node for the target with the
   labels and the shapes of "Links". Join it to the start node with a dotted edge and the verb:
   `s0 -.-|writes| x0`.

## Page

Header: `## <project>/<page>`. One `flowchart LR`:

1. A start node `s0(["<entry>"])`.
2. One node for each `## <action>` of `actions.md`: `a1["<action>"]`. Join it to the start
   node: `s0 --> a1`. A page does not run its actions in order. Do not join two actions.
3. For each `Call:` of an action, add a node for the target with the labels and the shapes of
   "Links", and
   an edge `a1 -->|calls| t0`. Use one node for a target that more than one action calls.
4. Add the `Then:` and `Fail:` bullets to the label of the action, after `<br/>✓ ` and
   `<br/>✗ `.

## Order

Write the diagrams of the flows and pages after `## Links`, per project in the order of
`config.json`, then by folder name.

Example: see `examples/mermaid.md`.
